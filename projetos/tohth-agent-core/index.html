T.O.H.T.H — Agente de IA pessoal

Batizado em homenagem a Thoth, o deus egípcio da escrita e do conhecimento. Um assistente de IA pessoal estilo J.A.R.V.I.S que roda de forma gratuita e privada, sem depender de assinaturas de nuvem — núcleo local + console web em tempo real.

LLM
100% local (Ollama)
Custo
Zero — sem APIs pagas
Interface
Console web em tempo real

Resumo do projeto

O cérebro do agente é um modelo de linguagem local servido pelo Ollama; sobre ele foi construída uma camada de orquestração que dá ao modelo persona, memória persistente e acesso a ferramentas externas. Além do núcleo em Python, o projeto inclui um console web em React que se conecta ao backend por WebSocket e exibe, em tempo real, a transcrição do usuário, a resposta do agente token a token e cada chamada de ferramenta — tudo com identidade visual inspirada na iconografia egípcia.

O que o sistema faz

  • Conversação com um LLM rodando 100% na máquina do usuário (privacidade total, custo zero).
  • Memória persistente: fatos marcados pelo usuário são gravados em disco e reinjetados no contexto das conversas seguintes.
  • Ferramentas: previsão do tempo (Open-Meteo), busca na web (DuckDuckGo) e envio de e-mail (SMTP).
  • Persona fixa — o agente responde sempre como "o escriba dos deuses", com tom consistente.
  • Console web em tempo real com streaming de respostas, status de conexão e histórico visual da sessão.
  • Caminho pronto para evoluir para voz (STT/TTS locais) e visão por câmera.

Arquitetura

Console Web (React)
⇄ WebSocket ⇄
Orquestrador (Python)
→
Ollama (LLM local)

O orquestrador é o centro do sistema: recebe a mensagem, decide se ela deve ser resolvida por uma ferramenta ou pelo modelo, monta o prompt com persona + memória + histórico, chama o Ollama e devolve o resultado. O front-end não conhece o LLM: ele apenas fala o protocolo de eventos.

Protocolo de comunicação

Toda a integração entre backend e interface acontece por mensagens JSON. O campo done permite streaming: enquanto for false, o texto é concatenado à bolha em construção.

DireçãoExemplo
Backend → interface{"type":"assistant","text":"Consultando os céus…","done":false}
Interface → backend{"type":"user_message","text":"bom dia"}

Interface (console web)

  • Campo de URL do WebSocket com persistência em localStorage — reconecta no mesmo endpoint entre sessões.
  • Indicador de estado do canal: selado (desconectado), invocando (conectando) e canal aberto (conectado).
  • Bolhas distintas por origem: usuário, agente, ferramenta invocada e eventos de sistema.
  • Cursor pulsante durante o streaming, auto-scroll e foco automático no campo de entrada.
  • Identidade visual: paleta obsidiana, papiro, ouro, laranja e carmim; tipografia Cinzel + Rajdhani + JetBrains Mono; moldura ritual com efeito scanline e hieróglifos no estado vazio.

Desafios e soluções

  • Streaming sem travar a interface: em vez de recriar a lista de mensagens a cada token, a resposta parcial é acumulada na última bolha marcada como parcial.
  • Reconexão e falhas de rede: URLs inválidas e quedas de canal viram eventos de sistema visíveis, em vez de erros silenciosos no console.
  • Custo zero: nenhuma API paga — modelo local e serviços abertos, o que também garante que nenhum dado da conversa saia da máquina.
  • Desacoplamento: o protocolo JSON permite trocar o LLM ou adicionar voz e visão sem tocar no front-end.

Próximos passos

  • Voz de ponta a ponta: Whisper.cpp para transcrição e Piper para síntese, com detecção de fala (VAD).
  • Visão: envio periódico de quadros da webcam para um modelo multimodal local.
  • Memória semântica com embeddings e busca vetorial, substituindo o JSON plano.
  • Classificador leve de intenção para escolher a ferramenta antes de acionar o LLM principal.

O que este projeto demonstra

  • Integração de LLMs locais em uma aplicação real, com orquestração e uso de ferramentas.
  • Comunicação em tempo real full-stack via WebSocket, com streaming incremental.
  • Design de protocolo desacoplado entre backend e front-end.
  • React moderno com SSR, gerenciamento de estado e UI com identidade visual própria.
  • Preocupação com privacidade, custo e possibilidade de execução offline.
